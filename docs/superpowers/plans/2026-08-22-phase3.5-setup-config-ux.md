# Phase 3.5 Setup & Configuration UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the Phase 3.5 spec (`docs/superpowers/specs/2026-08-21-phase3.5-setup-config-ux-design.md`): settings in the DB, config-health warnings + verdict degradation labeling, Admin page with danger zone, insert-parent + pipeline view, and the quick-setup wizard.

**Architecture:** New `Settings` KV table with `SettingsStore` feeding verdict/retention values; `ConfigHealth` evaluator; admin/setup endpoints in ConWatch; `IGatewayDiscovery`/`IWanAddressProbe` in ConInfrastructure behind interfaces (fakes in tests); wizard and admin as server-rendered Razor + small vanilla JS; pipeline view derived from the existing tree.

**Tech Stack:** unchanged (EF Core/SQLite, minimal APIs, Razor Pages, xUnit; hand-rolled SSDP/SOAP for UPnP-IGD — no new packages).

## Global Constraints

- **NEVER `git push`.** Branch `phase3.5`; commit per task; all suites (70 + 41 + 22 xUnit, 26 Vitest) stay green throughout.
- Setting keys (exact strings): `Verdict.AnchorPool`, `Verdict.WeatherThreshold`, `Retention.MinuteRetentionDays`, `Retention.HourlyRetentionMonths`, `Retention.RetentionRunHourUtc`, plus `Retention.LastRunUtc` (written by the retention service, shown on Admin).

- Wizard is additive only; names that already exist are skipped. Danger-zone confirmations: request body `{"confirm":"CLEAR"}` / `{"confirm":"RESET"}` (exact, case-sensitive) else 400.
- Wizard anchor catalog (server-side): Google 8.8.8.8, Cloudflare 1.1.1.1, Quad9 9.9.9.9, OpenDNS 208.67.222.222.
- Gateway probe candidates: 192.168.0.1, 192.168.1.1, 10.0.0.1, 10.0.0.2, 192.168.100.1 (1 s ping each), plus host default-route gateways.

### Task 8: Gateway discovery + WAN probe + setup API

**Files:** Create `ConInfrastructure/Discovery/IGatewayDiscovery.cs` (+`GatewayDiscovery`), `ConInfrastructure/Discovery/IWanAddressProbe.cs` (+`UpnpWanAddressProbe`), `Programs/ConWatch/SetupService.cs`, `Programs/ConWatch/Api/SetupEndpoints.cs`. Tests: `Tests/ConWatch.Tests/SetupApiTests.cs` (fake discovery/probe via factory overrides), `SetupServiceTests` in ConWatch.Tests (unit, in-proc services).

**Interfaces:**

```csharp
public record GatewayCandidate(string Address, string Source, bool Reachable, long? RttMs); // Source: "default-route" | "probe"
public interface IGatewayDiscovery { Task<IReadOnlyList<GatewayCandidate>> DiscoverAsync(CancellationToken ct); }

public record WanProbeResult(string? Address, string? FailureReason, bool PingOk, long? RttMs);
public interface IWanAddressProbe { Task<WanProbeResult> ProbeAsync(CancellationToken ct); }

public record SetupApplyRequest(SetupTarget Router, SetupTarget? OuterIp, List<string> AnchorAddresses);
public record SetupTarget(string Name, string Address);
public class SetupService(ConfigService config, ConfigStore store, SettingsStore settings, ILogger<SetupService> log)
{
    // Additive apply per spec §6.4: skips existing names/addresses; chains
    // Router -> OuterIp? -> anchors (External) -> pool "Internet" -> settings.
    public Task<ConfigResult> ApplyAsync(SetupApplyRequest request);
}
```

`GatewayDiscovery`: `NetworkInterface.GetAllNetworkInterfaces()` → operational, non-loopback → `GetIPProperties().GatewayAddresses` IPv4 (Source "default-route"); union with the constant candidate list; ping each once (1 s) for `Reachable`/`RttMs`; dedupe by address, default-route entries first.

`UpnpWanAddressProbe`: SSDP M-SEARCH over UDP to 239.255.255.250:1900 (`ST: urn:schemas-upnp-org:device:InternetGatewayDevice:1`, MX 2, 3 s listen) → parse `LOCATION` header → GET device XML → find `WANIPConnection`(or `WANPPPConnection`) `controlURL` → SOAP POST `GetExternalIPAddress` → parse `<NewExternalIPAddress>`. Any failure step returns `FailureReason` (no reply / no WAN service / SOAP error). On success, ping the address once (2 s) for `PingOk`/`RttMs`. All timeouts bounded; total ≤ ~8 s.

Endpoints: `GET /api/v1/setup/gateway` → candidates; `POST /api/v1/setup/wan-probe` → result; `POST /api/v1/setup/apply` → 204/400 via `ConfigResult`; anchor catalog exposed at `GET /api/v1/setup/anchors` (name/address list, server-side constant).

- [ ] Failing tests (fakes): apply builds the full chain + pool + settings on empty DB; apply is additive (re-run skips existing, adds only the new anchor); apply with OuterIp chains anchors under it; gateway endpoint returns fake candidates; wan-probe endpoint passes through failure reason. Real `UpnpWanAddressProbe`/`GatewayDiscovery` get construction/timeout smoke only (no network assertions in CI).
- [ ] Implement; suites green; commit `feat: gateway discovery, UPnP WAN probe, setup API`.
